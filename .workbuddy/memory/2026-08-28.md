# 2026-08-28

## 刷题模式 bug 修复（点击直接跳题、不显示答案、不再 5 题一轮）

**现象（用户截图反馈）**：刷题模式下点选项后不锁题显示答案，而是直接跳下一题，且轮次不再固定 5 题。

**根因**：2026-08-26 引入的 `antiRepeat` 防重复模式（commit `cfa6d6a`，默认开）后，`practiceList()` 每次调用都重新按 `practice.answers` 划分未答/已答池 → 洗牌 → 抽前 N。用户答一题后 `answers` 多 1 条 → 未答池缩短 → 洗牌结果与上一次不同 → `currentIdx` 对应的题号在新 list 里变成别的一道题 → 表现为「点选后没显示答案就跳题」。5 题一轮的感知丢失也缘于此（list 在变）。

**修复（index.html 单文件）**：给 `practiceList()` 加 list 缓存。
- key（不含 `practice.answers`）= 日期 + domainFilter + sourceFilter + todaySeed + pickSize + shuffle + antiRepeat。
- 命中缓存直接返回，答一题不触发重算 → `currentIdx` 锁定的题始终在原位，点选后 `locked:true` 显示答案/解析 + 「下一题」按钮。
- 清缓存触发点：`resetPractice()`、`#btn-shuffle`/`#btn-anti`/`#btn-wrong`/`#btn-back-all` 开关、`#src-chips`/`#dom-chips` 域/来源切换、`startBankPractice()`、换种子（shuffle 按钮）。
- `wrong` / `__wrong_today__` 模式不缓存（需跟随 answers 实时）。
- 顺手补全 antiRepeat 的 `unans=0` 回退分支（之前漏抽 N 逻辑，现统一成 `out` 变量）。

**复现/验证（headless chrome CDP，`.tmp/diag_quiz_click.js`）**：四场景全过 ——
- A) 答第1题后 `curIdx` 不变、`hasFb:true, locked:true, hasNext:true`，listIds `[132,160,9,225,131]` 稳定；
- B) 切 shuffle → list 重算为 `[5,6,7,8,9]`；
- C) 切 antiRepeat → list 重算 `[206,224,131,246,159]`；
- D) 点「下一题」→ `curIdx 0→1`、list 仍稳定 `[10,206,126,130,129]`、`#207/247`。

**坑回顾**：`file://` 下 localStorage 被禁 + 页面自带 fake-localStorage fallback 覆盖注入状态 → 诊断必须起本地 HTTP 静态服务器（`127.0.0.1`）绕过。模型不能读截图 → 改读代码 + headless 复现。

**待办**：`git add index.html && commit && push`（用户确认后再推）。
