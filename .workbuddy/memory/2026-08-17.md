## 博士推荐信策略·关键纠偏（续上午）
- 用户质疑：当前研究方向与硕士课题完全无关，日本硕士导师推荐信「没用」。
- 核实交大简章（WebSearch）：电院/机动/智慧能源 2026 非全工程博士均明文「至少 2 封副教授以上推荐信，**其中 1 封必须是硕士导师**」——此为**硬性强制项**，绕不开。
- 关键结论（已重写 phd 页，commit fbfb1fb）：
  - **第 1 封（强制·低分量）= 日本硕士导师**：只须他愿意写 + 高校邮箱能收系统信；信写硕士期间品格/能力，**不要求与当前方向一致**（招生委员会本就预期硕士导师来自硕士领域，属「品格背书」）。用户担心的「方向没关系」不是问题。
  - **第 2 封（关键·高分量）= 当前领域的人**（须报考学科领域内副教授以上）：真正决定专业说服力；写这封的人现在可能还不存在，要靠未来 2 年通过实际工作建立。
  - 因此「养人脉」真正目标 = 经营当前单位主管（非全双导师制行业导师天然人选）/ 研究合作者 / 目标院系意向导师，而非续旧日本导师。
  - 这彻底纠正了上午把「日本导师续旧」标为最紧迫的错误：它只是强制但低分量的形式项。
- 改动点：§5.1 重写为「两封分工」+ 硬规定 callout；§5.3 硬约束加简章出处；材料清单/任务 A01/A02/B02/B10 措辞同步调整（A02、B10 标 📌 重点=第2封当前领域关系）。
- 来源：literature 仓库显示用户当前真实研究为「第一人称数据科学 / N=1 健康数据 / ASD 遗传 / 数据工程」，与硕士课题无关——这正是第 2 封需从当前领域新建关系的根本原因。

## 博士申请页新增「读博路径决策看板」（commit ed11513）
- 背景：用户纠结两条路——A 交大非全工程博士 / B 创新交叉项目，但分叉点约 2027 下半年，现在只需打共同地基。
- 实现：在 phd 页顶部插入决策看板（三栏网格）：
  - 共同地基（4 项：电力IoT论文/软著、N=1积累、CDGA·CDGP、读文献建连接）+ 进度条
  - 路径A 倾向信号（3：单位主管愿当行业导师 / 论文落数据工程 / 读到交大导师有共鸣）
  - 路径B 倾向信号（3：想跳槽 / 论文更适合交叉 / 遇赏识杂兴趣的导师）
  - 各卡底部信号亮起提示句。
- 持久化：新增 initDecisionGroup，按 bb-phddecision-{base|A|B} 独立存储，进度条实时更新；材料清单改为 initGenChecks('phd','phd-mat-list') 以隔离。
- 验证（jsdom）：三组独立持久化正确、进度条/文案实时、重进页面状态保留、0 个 JS 错误。
- 关键洞察：用户兴趣杂、跨新领域、主线未定；看板不替他决策，只帮建地基+记信号，分叉时自然浮现。
