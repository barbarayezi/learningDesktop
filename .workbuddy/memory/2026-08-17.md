## 同步/数据库诊断（2026-08-17 晚）
- 用户问：http://192.168.71.53:8080/ 的数据是否到处都一样？数据库同步是否有问题？
- 结论：**计划内容(每天学什么/视频/路线图)是静态文件硬编码，到处完全一样，不依赖数据库**。
- **学习进度(打卡/勾选/主题)走 CloudBase**：浏览器 localStorage → 经 proxy_server.py 的 `/api/*` → CloudBase PostgreSQL(env=test-d5gf0o9ky7d34beaf, 表 user_data)。已实测匿名登录+读库 HTTP 200，库里含今天 cdga-daily-checks/cdga-video-watched-v1，同步链路是通的。
- 真正导致「感觉不同步」的 3 点：
  1. **粗粒度覆盖(clobber)**：每种进度是「一个 key = 整个 JSON blob」(如 cdga-daily-checks 存全部天)。`saveDailyChecks` 整 blob 覆盖。两个设备同时开着、各打卡→后保存的覆盖前一个→丢失。这是最可能的“同步问题”根因。
  2. **仅在打开页面时拉取云端**：已开着的标签页不会自动反映别的设备的改动，必须刷新。
  3. **本地兜底**：若 HTML 不是经本 proxy 打开(file:// 或直接双击、或 proxy 没跑)，`cloudReady=false`→纯 localStorage，数据永不出本浏览器。
- 澄清：`proxy_server.py` 里 `CLOUDBASE_KEY`(JWT) 其实 2025-08-16 09:00 已过期，但 proxy_request 只转发浏览器匿名登录拿到的 Bearer token，**根本没用这张静态密钥**——它是死代码，同步与其无关。
- 修复方向(用户未确认是否做)：把 initCloud 的「云端覆盖本地」改为「云端与本地 JSON 深合并」+ 写入前先 fetch-merge-upsert，可基本消除 clobber。
