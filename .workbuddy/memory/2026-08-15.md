## 2026-08-15 第三次迭代：阅读原文链接修复 + md bug 重现

### 1) 「阅读原文 ↗」改造成「🔍 微信内搜」+「📋 复制出处」
- **用户截屏**：每日中心的「📰 今日推文」底部点「阅读原文」→ 外链显示「链接已过期」。
- **根因**：每日中心 + 公众号推文精选两处的 `<a class="news-read" href="${art.url}">` 指向 `weixin.sogou.com/link?url=...` 这种**搜狗微信搜索中转 URL**，几天到几周后公众号文章下线或被举报就 404。118 篇里有 82 篇没内嵌全文（仅有点要点），所以「阅读原文」是唯一出路——但它失效率高得不能接受。
- **改造方案（两处 + 全局监听）**：
  - `<a class="news-read" 阅读原文 ↗</a>` → 两个 `<button>`：
    - `🔍 微信内搜`：`data-title="${art.title}"`，点击 `window.open('https://weixin.sogou.com/weixin?type=2&ie=utf8&query=' + encodeURIComponent(title))`。搜狗搜索 URL 本身不会过期，结果是真实公众号文章。
    - `📋 复制出处`：`data-url="${art.url}"`，写 `navigator.clipboard.writeText`，弹底部 toast。
  - 加 `showToast()`（插入 `<div id="toast">`）+ 全局 `document.addEventListener('click', …)` 拦截 `.news-search` / `.news-copy`。
  - **file:// 兼容性**：`navigator.clipboard` 在 `file://` 下被禁（不满足 secure context），加 `document.execCommand('copy')` 的 textarea fallback。
  - CSS：`.news-read` 加 `border:none; cursor:pointer; display:inline-flex` 让 `<button>` 长得跟原 `<a>` 一致；`.news-foot` 加 `flex-wrap` 防窄屏溢出。

- **验证**：内联脚本 0 错误；旧 `<a class="news-read">` 计数 0；2 处都换成 2 个 button；showToast / addEventListener 各 1 处；URL encode 验证 OK。

### 2) Patch 流程踩坑（避免再犯）
- **坑 1**：用 `node` 脚本 + `s.replace()` 做字符串 patch 时，**在 template literal 里写 JS 代码一定要重新拷一遍**。这次我在 `/tmp/patch_wechat_link.js` 的 template literal 里手抖把 `const fail=()=>{` 写成 `const fail=()>{`（少了 `=`），结果 Node `--check` 报「Unexpected token ')'」指向那一行——而我反复 bisect 还以为是更早的代码出问题，浪费了好几轮。
- **教训**：
  - 写完 patch script **立刻 `node --check <extracted_script>`**，不要相信肉眼检查。
  - Node 报错位置可能会指错行（因为语法错误暴露点 ≠ 出错点），但只要 `node --check` 0 error 就是 OK 的；不要试图从 bisect 反推 bug 行。
  - diff 工具要带 `--from-file/--to-file` 而不是只 diff 行——这次是字节级差异，肉眼一样但 hex 不同。
- **坑 2**：Chrome `file://` 下不能用 `fetch` 拿到同目录的 `.md`。**当前对策（commit c3d92c0）**：把要展示的 .md 内容**内嵌**为 `<template id="mdSrc-{key}">…</template>`，openReader 读 `tpl.content.textContent` 绕过 fetch。后续若加新 .md 资源，必须同步加 template，否则又会被截屏揭穿「没渲染」。
