## 09:25 boot 队列架构改造（任设备自动同步，零手动操作）
- **用户原话**：「能不能确保无论我到哪台电脑上打开这个网页，数据都是同步一致的？不要有任何让用户强算之类的操作」
- **根因**：原 initCloud 是 IIFE 立即执行 + 完成后 1.2s 强制 reload，UI 渲染走在云端拉取之前，依赖 reload 才能看到完整数据。
- **改造方案**：
  1. body 开头加 `#bootSplash` 全屏遮罩（z-index 99998，含 ☁️ 图标 + "正在同步学习记录…"）
  2. `(async function initCloud(){...})()` 改 `async function initCloud(){... return bool}`，去掉 IIFE 立即执行和 reload 段（didChange 变量也删）
  3. 引入 boot 队列：`_bootTasks[]` + `function boot(label,fn){...}` 替代顶层 `safe('...')`（19 处），延迟到 initCloud 完成后执行
  4. boot 队列最前插入「存储快照重载」：重新 load 5 个 `let X = loadXxx()` 模块级快照（dailyChecks/notes/daynotes/videoWatched/wbSubMode），这些在脚本顶层立即赋值（merge 前=空），是热力图等用旧值的根因
  5. 文件尾 `(async function bootAll(){ await Promise.race([initCloud(), timeout 7000ms]); ... }())`：7s 超时兜底（云端失败按本地数据渲染）、splash 0.3s 淡出
  6. 独立 15s setTimeout 兜底（主脚本异常时强制隐藏 splash，不至于页面永远盖住）
- **CI 验证**（headless dump-dom + console）：
  - splash display:none ✓
  - 19 模块全部 OK（console 打印 "✅ 页面渲染完成，共执行 19 个模块"）
  - initCloud 21 条数据同步 ✓
  - 热力图 hl-done=19（云端 18 天打卡 + 今日）✓
  - 勾选 chk-row done=8（云端 bb-cdga-check 8 个 true）✓
  - 错误红条 0 ✓
  - 5 条 W3 锚点式拆解正确渲染 ✓

## 跨设备自动同步架构最终形态
- 任何设备打开网页 → 0.3-1s 内看到 bootSplash（"正在同步学习记录…"）→ initCloud 拉 Cloudflare Worker → 深合并 localStorage → boot 队列渲染 UI → splash 淡出 → 完整内容
- **零手动**：无需 Cmd+R、无需 Cmd+Shift+R、无需清缓存、无需「强制刷新」
- **零闪烁**：没有「先空再 reload 再满」的视觉跳变
- **失败兜底**：云端 7s 超时按本地数据渲染、15s 终极隐藏 splash
