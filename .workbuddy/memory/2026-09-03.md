## 修复 daily card → 做题页「跳到做过的题」bug

### 用户现场
- 图1：每日中心「刷题 数据仓库与BI (4/16 题·优先未答·每日抽 5)」
- 图2：跳到做题页直接是 #167/247，B 标绿对勾，显示「✅ 回答正确」
- 题目：维度建模中的"事实表"存储？a='B'（QUIZ[166]）

### 根因（拆解 5 步）
1. 原 line 5288 `applyQuizMode()` 在脚本顶层立即执行，**早于 bootAll() 内的 initCloud**
2. 那次 `loadPractice()` 灌进内存的是 localStorage **旧值**（device merge 之前）
3. boot 任务「存储快照重载」只重载 day/notes/video，**未重载 practice**
4. 结果：内存与 disk 错位 → daily card 的 done 算的是 stale 值
5. 用户点 daily card → openQuiz → savePractice 把 stale 写回 disk
   **覆盖 initCloud merge 结果** → loadPractice 重读 → list 把云端已答
   当成「未答」抽进 unans 池 → 渲染时显示「做过的样子」

### 修复
- `index.html` line 3201 boot 任务「存储快照重载」加 `try{ loadPractice(); }catch(e){}`
- 把脚本顶层 `applyQuizMode()`（原 line 5288）移到 boot 队列「刷题模式初始化」
  等 initCloud + loadPractice 完成后再渲染

### 顺手发现/清理
- 把 boot 任务从「热力图」到「打开默认页」之间的"刷题模式初始化"注册
  时，**错误地同时把 fake `boot('刷题模式初始化', function(){ applyQuizMode(); });` 写在了
  注释里**。改进 `bootCallbackCallsReal()` 用 `lastIndexOf` 找最后一次出现，并去除行
  内 `//` 注释后扫描，避免假命中。
- `bootCallbackCallsReal()` 改进了函数体结束识别——原来 `'\n});'` 单行匹配失败
  （单行 boot 任务如 `function(){ applyQuizMode(); }` 没有 `\n` 在 `});` 前），
  改为同时支持 `});` 紧跟分号。

### 教训
- 任何「内存与 disk 同步」类的操作（loadPractice / loadChecks / 等）必须
  显式列在 boot 任务里，不能依赖其他模块顺带触发
- 静态断言（"boot 任务含 X 调用"）要排除注释行 & 注释里的字面量，
  用 `lastIndexOf` + 去注释扫描
- 受控崩溃测试（"临时移除修复 → 断言变红"）要每次加新断言都跑，
  否则测试可能永远绿
