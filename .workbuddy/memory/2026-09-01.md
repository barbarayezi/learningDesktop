## reveal gate 不再依赖 .revealed class（commit 493cef9，已上线公网）

**用户三次反馈**：截图显示 row 1 答案区**视觉已展开**（点过「先自己想」），但点「△ 一部分」仍弹「🤔 请先点『展开答案』回忆一下，再评掌握度」。

**根因**：原 gate
```js
const revealed = itemEl && itemEl.classList.contains('revealed');
```
依赖 JS 给 itemEl 加 `.revealed` class，"先展开答案"按钮 click handler 里写的是 `itemEl.classList.add('revealed')`——但**用户的浏览器可能仍跑着历史上某个漏 add 的版本**（或本地 DOM 状态在 renderDay 重建时丢 class），视觉 `ans.hidden=false` 生效（答案区显出）但 class 同步上没加上，gate 误判未揭示 → 拦截。

**修复**：gate 改读答案区 DOM 的原生 `hidden` boolean 属性，是更可靠的真相源：
```js
const ansDiv = itemEl && itemEl.querySelector('.dc-review-a');
const revealed = !!(ansDiv && !ansDiv.hidden);
```
只要 reveal 流程走过 `ansDiv.hidden = false` 就视为已揭示，与 class 同步状态解耦。

**公网验证**：size 578520→578887；`ansDiv && !ansDiv.hidden` 命中 1，老 gate `classList.contains('revealed')` 已不在 review click handler 里（search 0 命中）

**教训**：DOM 的原生 boolean 属性 / 元素的实际状态，比"为它单独维护一个 class"更可信。后续遇到"视觉到位但 class 状态不对"的拦截时，优先迁移到查 DOM 状态。
